2) Architect Mindset (keywords India panel likes)

  • Methodology over scripts: discovery, design, build, rehearsal, cutover, hypercare.
  • Design for failure: checkpoint, restart, idempotent jobs, rollback gates.
  • Data quality first: reject dirty data into quarantine, do not contaminate target core.
  • Reconciliation is non-negotiable: ETL success is not migration success.
  • Governance and control: lineage, ownership, maker-checker approvals, auditable logs.

3) Delivery Storyline (2-minute summary)

  • Started with source profiling and critical data element inventory.
  • Designed metadata-driven migration engine and reconciliation framework.
  • Executed dry-runs, tuned bottlenecks, reduced cutover window iteratively.
  • Prepared minute-by-minute runbook and objective rollback criteria.
  • Go-live decision based on data parity + business sign-off + operational SLA.

4) ERD Blueprint for Corporate Banking (example)

CUSTOMER (customer_id PK, segment, kyc_status)
  1 - N ACCOUNT (account_id PK, customer_id FK, product_id FK, branch_id FK, status, currency)
  1 - N KYC_PROFILE (kyc_id PK, customer_id FK, risk_rating, review_date)

ACCOUNT (account_id PK)
  1 - N TXN (txn_id PK, account_id FK, txn_ts, value_date, amount, dr_cr_flag, channel_code)
  1 - N ACCOUNT_BALANCE_DAILY (account_id FK, balance_date, closing_balance)

PRODUCT (product_id PK) 1 - N ACCOUNT
BRANCH  (branch_id PK)  1 - N ACCOUNT

Integrity Rules:
1) TXN.amount is NUMBER(18,2) and not null
2) ACCOUNT_BALANCE_DAILY unique(account_id, balance_date)
3) FK constraints validate after bulk load
4) No orphan account/customer records

5) Sample SQL/DDL for Interview Whiteboard

Table design

CREATE TABLE txn (
  txn_id        VARCHAR2(40) PRIMARY KEY,
  account_id    VARCHAR2(30) NOT NULL,
  txn_ts        TIMESTAMP NOT NULL,
  value_date    DATE NOT NULL,
  amount        NUMBER(18,2) NOT NULL,
  dr_cr_flag    CHAR(1) NOT NULL CHECK (dr_cr_flag IN ('D','C')),
  channel_code  VARCHAR2(10),
  CONSTRAINT fk_txn_account FOREIGN KEY (account_id)
    REFERENCES account(account_id)
);

Performance examples

-- Range partition for large transaction table
PARTITION BY RANGE (value_date)

-- Useful local index pattern
CREATE INDEX idx_txn_acc_date ON txn(account_id, value_date);

6) Reconciliation SQL (3-layer)

-- Layer 1: row count parity
SELECT COUNT(*) FROM src.txn WHERE value_date = :biz_date;
SELECT COUNT(*) FROM tgt.txn WHERE value_date = :biz_date;

-- Layer 2: financial parity
SELECT SUM(amount) FROM src.txn WHERE value_date = :biz_date;
SELECT SUM(amount) FROM tgt.txn WHERE value_date = :biz_date;

-- Layer 3: checksum parity
SELECT STANDARD_HASH(
  account_id || '|' || TO_CHAR(value_date,'YYYYMMDD') || '|' || TO_CHAR(amount),
  'SHA256'
) AS row_hash
FROM src.txn
WHERE value_date = :biz_date;

  • Situation: legacy core banking constraints, strict cutover window.

  • Risk control: checkpoint restart and rollback plan validated in dry-run.
